# Сети в Linux

Настройка сетей в Linux на виртуальных машинах.

## Introduction

В данном проекте выполнены задачи по настройке сетей на виртуальных машинах под управлением 
Ubuntu 20.04 Server LTS. В рамках работы использовались утилиты `ipcalc`, `ip`, `netplan`, 
`netstat`, `iperf3`, `iptables`, `ping`, `nmap`, `sysctl`, `tcpdump`, `traceroute`, `systemctl`, 
`telnet`, `dhclient`, `isc-dhcp-server`, `apache2`.

## Part 1. Инструмент ipcalc

- Определен адрес сети `192.167.38.54/13`.
- Выполнен перевод масок из одной записи в другую (префиксная, обычная, двоичная).
- Определены минимальные и максимальные хосты в сети `12.167.38.4` с заданными масками.
- Проверена возможность обращения к приложению на localhost со стороны заданных IP-адресов.
- Выполнено разделение IP-адресов на публичные и частные.
- Определены возможные IP-адреса шлюза для сети `10.10.0.0/18`.

## Part 2. Статическая маршрутизация между двумя машинами

- Подняты две виртуальные машины (ws1 и ws2).
- Изучены сетевые интерфейсы с помощью команды `ip a`.
- Настроены сетевые интерфейсы в файле `/etc/netplan/00-installer-config.yaml` (ws1 — `192.168.100.10/16`, ws2 — `172.24.116.8/12`).
- Применены настройки командой `netplan apply`.
- Добавлен статический маршрут вручную командой `ip r add` и проверено соединение (`ping`).
- Добавлен статический маршрут с сохранением через конфигурационный файл, проверено соединение (`ping`).

## Part 3. Утилита iperf3

- Переведены единицы измерения скорости соединения (Mbps, MB/s, Kbps, Gbps).
- Измерена скорость соединения между ws1 и ws2 с помощью утилиты `iperf3`.

## Part 4. Сетевой экран

- Создан файл `/etc/firewall.sh` для имитации файрвола.
- Настроены правила `iptables` на ws1 (запрещающее, затем разрешающее) и ws2 (разрешающее, затем запрещающее).
- Открыт доступ для портов 22 (ssh) и 80 (http).
- Настроены правила блокировки и разрешения *echo reply* (ICMP).
- Запущены файлы на обеих машинах, описана разница между стратегиями.
- С помощью `ping` найдена машина без ответа, а с помощью `nmap` подтверждено, что хост запущен (`Host is up`).
- Сделаны дампы образов виртуальных машин.

## Part 5. Статическая маршрутизация сети

- Подняты пять виртуальных машин (ws11, ws21, ws22, r1, r2).
- Настроены конфигурации машин в `/etc/netplan/00-installer-config.yaml`, проверены адреса (`ip -4 a`) и доступность (`ping`).
- Включена переадресация IP-адресов командой `sysctl -w net.ipv4.ip_forward=1` и через файл `/etc/sysctl.conf`.
- Настроен маршрут по умолчанию (шлюз) для рабочих станций, проверен вывод `ip r`.
- Добавлены статические маршруты в файлы конфигурации роутеров r1 и r2.
- Проверен `ip r list` для адреса `10.10.0.0/[маска]` и `0.0.0.0/0`, объяснена разница выбора маршрутов.
- Построен список маршрутизаторов с помощью `traceroute`, проанализирован дамп `tcpdump`, объяснен принцип работы `traceroute`.
- Выполнен перехват сетевого трафика `ICMP` с помощью `tcpdump` при пинге несуществующего IP.
- Сделаны дампы образов виртуальных машин.

## Part 6. Динамическая настройка IP с помощью DHCP

- Настроена конфигурация службы DHCP на r2 (`/etc/dhcp/dhcpd.conf`), указаны маршрутизатор, DNS и адрес сети.
- В файл `/etc/resolv.conf` прописан `nameserver 8.8.8.8`.
- Перезапущена служба DHCP, ws21 перезагружена и проверено получение адреса (`ip a`), проверено соединение (`ping`).
- Задан MAC-адрес для ws11 (`macaddress: 10:10:10:10:10:BA`), настроена жесткая привязка на r1.
- Запрошено обновление IP-адреса на ws21 (сравнение IP до и после), описаны использованные опции DHCP.
- Сделаны дампы образов виртуальных машин.

## Part 7. NAT

- В файле `/etc/apache2/ports.conf` на ws22 и r1 изменен порт на `Listen 0.0.0.0:80`.
- Запущен веб-сервер Apache на ws22 и r1.
- Настроен фаервол на r2 (сброс правил, политика DROP для FORWARD).
- Проверена блокировка соединения между ws22 и r1 (`ping`).
- Добавлено правило для разрешения маршрутизации ICMP, проверено соединение.
- Настроены правила **SNAT** (маскирование локальных IP) и **DNAT** (порт 8080 на r2, доступ к Apache на ws22).
- Проверены соединения по TCP для SNAT и DNAT с помощью `telnet`.
- Сделаны дампы образов виртуальных машин.
